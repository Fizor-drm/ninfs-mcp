# ninfs-mcp Implementation Plan (rev5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ninfs CLIをsubprocessで駆動するstdio MCPサーバー (5ツール) のMVPを実装する。

**Architecture:** `policy.py` (三段パス判定・secrets集約・sanitizer・read-only強制) を土台に、`runner.py` が常駐 mount プロセス (`sys.executable -m ninfs` 起動→種別固有readiness→冪等停止) と `MountSession` 所有・逆順cleanup・残存管理を持ち (内部型を返す)、`server.py` がワーカースレッド経由で呼び、公開dictへの変換とID解決だけを行う。実機mountは全てmockし、単体試験のみで検証する。実機確認は手動 Task 6。

**Tech Stack:** Python (src layout), `mcp` (stdio server), `ninfs==2.0` (subprocess経由のみ、importしない), `pytest` (mockはstdlib `unittest.mock`)

**Spec:** `docs/superpowers/specs/2026-10-07-ninfs-mcp-design.md` (rev6)

## Global Constraints

- Windows + WinFsp 特化。実機mountの結合試験は手動 Task 6 とし、CI/単体試験では回さない。
- 接続は stdio。ninfs 起動は `sys.executable -m ninfs <kind>` に統一し (裸の `mount_*` 禁止)、全 mount に `-f` を付ける。`communicate` 待ちはしない。stdout は常に DEVNULL。
- mount は全て read-only 強制 (`sd` のみ `--ro` 指定、他は組込み固定)。SD への write API・削除 API は作らない。
- AI に任意コマンド実行は渡さない。公開ツールは5個のみ。
- `sanitize(text, secrets)` の secrets は必須引数。選択 SD パスは runner が保持し、残存にもスナップショットを持たせる。
- ファイル内容は MCP 応答に含めない。成功証拠は `code-decompressed.bin` の存在のみ。
- 全 `pip`/`python` 呼出しは `python -m ...` 形式に統一する。
- 各実装コミット後に `security-audit` を `quick` で実行し、`confirmed` を解消、`needs_validation` を確認する。完了後に独立 Review を受ける。

- Create: `src/ninfs_mcp/__init__.py`

固定シグネチャ (全タスク共通、変更禁止):

```python
# policy.py
def resolve_dest(workspace: Path, dest_rel: str) -> Path: ...
def check_no_overlap(workspace: Path, sd_root: str) -> None: ...
def sanitize(text: str, secrets: Iterable[str]) -> str: ...
def get_secrets(extra: Iterable[str] = ()) -> list[str]: ...
def reject_write_args(extra: Mapping[str, Any]) -> None: ...

# runner.py
@dataclass
class InternalMount:
    session_id: str
    kind: str
    mount_point: Path
    proc: Any
    handle_id: str | None
    secrets: list[str]          # sanitizer用スナップショット

@dataclass
class MountSession:
    mount_id: str
    staging: Path
    children: list[InternalMount]
    title_handles: dict[str, TitleHandle]
    sd_root: str

@dataclass
class TitleHandle:
    handle_id: str
    mount_id: str
    requested_title_id: str
    resolved_title_id: str
    kind: str
    tmd_found: bool
    tmd_path: str               # 内部用。公開しない

@dataclass
class ExtractResult:
    dest_path: str
    size: int
    sha256: str
    code_entry: str             # 常に "code-decompressed.bin"

@dataclass
class UnmountSummary:
    ok: bool
    incomplete: bool
    errors_sanitized: list[str]
    residuals: list[InternalMount]

def check_winfs() -> None: ...
def detect_sd(sd_root_override: str | None = None) -> dict: ...
def mount_sd() -> MountSession: ...
def find_title(session: MountSession, title_id: str) -> TitleHandle: ...
def extract_code(handle: TitleHandle, dest_rel: str) -> ExtractResult: ...
def unmount(mount_id: str) -> UnmountSummary: ...
def retry_residuals() -> int: ...
```

`detect_sd` のみ dict を返す (状態を持たない照会のため。server はそのまま公開形として返す)。

公開応答の完全形: `detect_sd` 4キー/`ambiguous`、`mount_sd` 2キー、`find_title` 5キー、`extract_code` 4キー、`unmount` 3キー、エラー共通形 3キー。

段別入力の確定値 (Task 1 Step 6 で照合。`python -m ninfs <kind>` 形式):

- sd: `--movable <f> --boot9 <b> --ro <dir> <mp> -f`
- sdtitle: `--boot9 <b> <tmdファイル> <mp> -f`
- ncch: `--boot9 <b> <0000.*.ncch> <mp> -f`
- exefs: `--decompress-code <exefs.bin> <mp> -f`

readiness の必須エントリ: sd=`<mp>/<ID1>/` 1件以上、sdtitle=`tmd.bin`、ncch=`exefs.bin`、exefs=`code-decompressed.bin`/`code.bin`。

環境変数: `NINFS_BOOT9_PATH`, `NINFS_MOVABLE_PATH`, `NINFS_SD_ROOT` (任意), `NINFS_WORKSPACE` (必須の絶対パス)。

## Review Focus

1. 常駐 mount 中も後続ツールが応答する → プロセス生存のまま返る (Task 2)。
2. `..` 成分・ドライブ・UNC・予約名・`.mounts` は形式拒否される (Task 1)。
3. 自動検出のSDパスを含め秘密が応答に出ない (Task 1・2・5)。
4. 展開失敗・未生成は成功扱いされない (Task 4)。
5. 削除済みIDの残存も再解除できる (Task 2・5)。
