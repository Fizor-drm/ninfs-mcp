# ninfs-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ninfs CLIをsubprocessで駆動するstdio MCPサーバー (5ツール) のMVPを実装する。

**Architecture:** `policy.py` (二段パス判定・sanitizer・secrets集約・read-only強制) を土台に、`runner.py` が常駐 mount プロセス (`-f` 起動→readiness→terminate確認) と `MountSession` 所有・逆順cleanup・残存管理を持ち (内部型を返す)、`server.py` が公開dictへの変換とID解決だけを行う。実機mountは全てmockし、単体試験のみで検証する。

**Tech Stack:** Python (src layout), `mcp` (stdio server), `ninfs` (CLI subprocess経由のみ、importしない), `pytest` (mockはstdlib `unittest.mock`)

**Spec:** `docs/superpowers/specs/2026-10-07-ninfs-mcp-design.md` (rev4)

## Global Constraints

- Windows + WinFsp 特化。実機mountの結合試験は手動とし、CI/単体試験では回さない。
- 接続は stdio。ninfs mount CLI は `-f` 付き常駐プロセスとして `Popen` 起動し、`communicate` 待ちはしない。
- mount は全て read-only 強制 (`sd` のみ `--ro` 指定、他は組込み固定)。SD への write API・削除 API は作らない。
- AI に任意コマンド実行は渡さない。公開ツールは5個のみ。
- `boot9.bin` / `movable.sed` の中身・SD復号キーを返さない。`get_secrets()` 集約以外の `sanitize` 呼び出しは禁止。
- ファイル内容は MCP 応答に含めない。`extract_code` はメタデータのみ返す。
- 各実装コミット後に `security-audit` を `quick` で実行し、`confirmed` を解消、`needs_validation` を確認する。完了後に独立 Review を受ける。

- Create: `src/ninfs_mcp/__init__.py`
- Create: `src/ninfs_mcp/policy.py` — `resolve_dest` / `sanitize` / `get_secrets` / `reject_write_args`。状態を持たない。
- Create: `src/ninfs_mcp/runner.py` — 内部型と5操作の実体。唯一状態を持つ。公開dictは返さない。
- Create: `src/ninfs_mcp/server.py` — 公開スキーマ・ID解決・内部型→公開dict変換。
- Create: `tests/test_policy.py`, `tests/test_runner.py`, `tests/test_server.py`。

固定シグネチャ (全タスク共通、変更禁止):

```python
# policy.py
def resolve_dest(workspace: Path, dest_rel: str) -> Path: ...
def sanitize(text: str, secrets: Iterable[str]) -> str: ...  # secrets必須引数
def get_secrets(extra: Iterable[str] = ()) -> list[str]: ...  # env + extraを集約
def reject_write_args(extra: Mapping[str, Any]) -> None: ...

# runner.py
@dataclass
class InternalMount:
    kind: str          # "sd" | "sdtitle" | "ncch" | "exefs"
    mount_point: Path
    proc: Any
    handle_id: str | None

@dataclass
class MountSession:
    mount_id: str
    children: list[InternalMount]
    title_handles: dict[str, TitleHandle]

@dataclass
class TitleHandle:
    handle_id: str
    mount_id: str
    requested_title_id: str
    resolved_title_id: str
    kind: str          # "base" | "update"
    tmd_found: bool
    tmd_path: str      # 内部用。公開しない

def check_winfs() -> None: ...                    # 分離subprocess。不可ならRuntimeError
def detect_sd(sd_root_override: str | None = None) -> dict: ...
def mount_sd() -> MountSession: ...               # 内部型を返す
def find_title(session: MountSession, title_id: str) -> TitleHandle: ...
def extract_code(handle: TitleHandle, dest_rel: str) -> ExtractResult: ...
def unmount(mount_id: str) -> UnmountSummary: ... # 内部型。残存は _RESIDUALS へ
def retry_residuals() -> int: ...                 # 回収数
```

公開応答の完全形 (server が変換。Task 4 がキー集合まで試験):

- `detect_sd` → `{"sd_root","has_n3ds_dir","has_boot9","has_movable"}` / `{"error":"ambiguous","candidates"}`。
- `mount_sd` → `{"mount_id","mount_point"}`。
- `find_title` → `{"requested_title_id","resolved_title_id","kind","tmd_found","title_handle"}`。
- `extract_code` → `{"dest_path","size","sha256","code_entry"}`。
- `unmount` → `{"ok","incomplete","errors_sanitized"}`。
- エラー共通形 → `{"error","message_sanitized","incomplete"}`。

段別入力の確定値 (実測):

- sd: `mount_sd --movable <f> --boot9 <b> --ro <dir> <mp> -f`
- sdtitle: `mount_sdtitle --boot9 <b> <tmdファイル> <mp> -f`
- ncch: `mount_ncch --boot9 <b> <0000.*.ncch> <mp> -f`
- exefs: `mount_exefs --decompress-code <exefs.bin> <mp> -f`

環境変数: `NINFS_BOOT9_PATH`, `NINFS_MOVABLE_PATH`, `NINFS_SD_ROOT` (任意), `NINFS_WORKSPACE` (必須の絶対パス。Task 4 の起動時に検証・作成)。

## Review Focus

1. 常駐 mount 中も後続ツールが応答する → `mount_sd` はプロセス生存のまま返る (Task 2)。
2. `..` 成分・ドライブ・UNC・予約名は内側に収まっても形式拒否される (Task 1)。
3. stderr/例外に秘密が混ざっても応答に出ない → `get_secrets` 経由でマスクされる (Task 1・2)。
4. 圧縮 `.code` で展開失敗は成功扱いされない → エラーになる (Task 3)。
5. 解除失敗残存は次回 `unmount`/終了時に再解除できる (Task 2・4)。

- [ ] **Step 3: Implement runner基盤**

`spawn_mount`: `-f` 必須 (無ければ `ValueError`)。stderr排出スレッドを起動直後に開始し、有界deque (末尾64KB) へ送る。
`wait_ready(mount_point, proc, predicate, timeout_s=10)`: 200ms間隔。predicate は種別固有 (sd: ID0様の非空内容、汎用: 非空 + proc生存)。タイムアウト時は `stop_proc` 後に sanitizer済み `RuntimeError`。

`unmount`: レジストリ即削除 → `cleanup_core` → 残存は `_RESIDUALS` へ移動 → 内部 `UnmountSummary`。
`retry_residuals`: `_RESIDUALS` を再試行し回収数を返す。
