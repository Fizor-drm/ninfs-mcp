# ninfs-mcp Implementation Plan (rev4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ninfs CLIをsubprocessで駆動するstdio MCPサーバー (5ツール) のMVPを実装する。

**Architecture:** `policy.py` (二段パス判定・secrets集約・sanitizer・read-only強制) を土台に、`runner.py` が常駐 mount プロセス (`-f` 起動→種別固有readiness→冪等停止) と `MountSession` 所有・逆順cleanup・残存管理を持ち (内部型を返す)、`server.py` が公開dictへの変換とID解決だけを行う。実機mountは全てmockし、単体試験のみで検証する。実機確認は手動 Task 5。

**Tech Stack:** Python (src layout), `mcp` (stdio server), `ninfs==2.0` (CLI subprocess経由のみ、importしない), `pytest` (mockはstdlib `unittest.mock`)

**Spec:** `docs/superpowers/specs/2026-10-07-ninfs-mcp-design.md` (rev5)

## Global Constraints

- Windows + WinFsp 特化。実機mountの結合試験は手動 Task 5 とし、CI/単体試験では回さない。
- 接続は stdio。ninfs mount CLI は `-f` 付き常駐プロセスとして `Popen` 起動し、`communicate` 待ちはしない。stdout は常に DEVNULL。
- mount は全て read-only 強制 (`sd` のみ `--ro` 指定、他は組込み固定)。SD への write API・削除 API は作らない。
- AI に任意コマンド実行は渡さない。公開ツールは5個のみ。
- `sanitize(text, secrets)` の secrets は必須引数。マスク対象は `get_secrets()` 集約 + runner保持の選択 SD パス。
- ファイル内容は MCP 応答に含めない。成功証拠は `code-decompressed.bin` の存在のみ。
- 全 `pip`/`python` 呼出しは `python -m pip` / `python -m ...` 形式に統一し、同一環境を保証する。
- 各実装コミット後に `security-audit` を `quick` で実行し、`confirmed` を解消、`needs_validation` を確認する。完了後に独立 Review を受ける。

固定シグネチャ (全タスク共通、変更禁止):

```python
# policy.py
def resolve_dest(workspace: Path, dest_rel: str) -> Path: ...
def sanitize(text: str, secrets: Iterable[str]) -> str: ...
def get_secrets(extra: Iterable[str] = ()) -> list[str]: ...
def reject_write_args(extra: Mapping[str, Any]) -> None: ...

# runner.py
@dataclass
class InternalMount:
    session_id: str
    kind: str          # "sd" | "sdtitle" | "ncch" | "exefs"
    mount_point: Path
    proc: Any
    handle_id: str | None

@dataclass
class MountSession:
    mount_id: str
    staging: Path
    children: list[InternalMount]
    title_handles: dict[str, TitleHandle]
    sd_root: str       # 選択SDパス。secrets供給用

@dataclass
class TitleHandle:
    handle_id: str
    mount_id: str
    requested_title_id: str   # 小文字正規化済み
    resolved_title_id: str    # 小文字正規化済み
    kind: str                 # "base" | "update"
    tmd_found: bool
    tmd_path: str             # 内部用。公開しない

@dataclass
class ExtractResult:
    dest_path: str
    size: int
    sha256: str
    code_entry: str           # 常に "code-decompressed.bin"

@dataclass
class UnmountSummary:
    ok: bool
    incomplete: bool
    errors_sanitized: list[str]
    residuals: list[InternalMount]  # _RESIDUALS へ移動した分

def check_winfs() -> None: ...
def detect_sd(sd_root_override: str | None = None) -> dict: ...
def mount_sd() -> MountSession: ...
def find_title(session: MountSession, title_id: str) -> TitleHandle: ...
def extract_code(handle: TitleHandle, dest_rel: str) -> ExtractResult: ...
def unmount(mount_id: str) -> UnmountSummary: ...
def retry_residuals() -> int: ...
```

`detect_sd` のみ dict を返す例外扱いとする。理由: 状態を持たない照会であり、内部参照を含まないため。server はそのまま公開形として返す (キー集合試験あり)。

公開応答の完全形 (server が変換。Task 4 がキー集合まで試験):

- `detect_sd` → `{"sd_root","has_n3ds_dir","has_boot9","has_movable"}` / `{"error":"ambiguous","candidates"}`。
- `mount_sd` → `{"mount_id","mount_point"}`。
- `find_title` → `{"requested_title_id","resolved_title_id","kind","tmd_found","title_handle"}`。
- `extract_code` → `{"dest_path","size","sha256","code_entry"}`。
- `unmount` → `{"ok","incomplete","errors_sanitized"}`。
- エラー共通形 → `{"error","message_sanitized","incomplete"}`。

段別入力の確定値 (実測。Task 1 Step 5 で照合):

- sd: `mount_sd --movable <f> --boot9 <b> --ro <dir> <mp> -f`
- sdtitle: `mount_sdtitle --boot9 <b> <tmdファイル> <mp> -f`
- ncch: `mount_ncch --boot9 <b> <0000.*.ncch> <mp> -f`
- exefs: `mount_exefs --decompress-code <exefs.bin> <mp> -f`

readiness の必須エントリ: sd=`<mp>/<ID1>/` が1件以上、sdtitle=`tmd.bin`、ncch=`exefs.bin`、exefs=`code-decompressed.bin` または `code.bin`。

環境変数: `NINFS_BOOT9_PATH`, `NINFS_MOVABLE_PATH`, `NINFS_SD_ROOT` (任意), `NINFS_WORKSPACE` (必須の絶対パス。Task 4 の起動時に検証・作成)。

## Review Focus

1. 常駐 mount 中も後続ツールが応答する → プロセス生存のまま返る (Task 2)。
2. `..` 成分・ドライブ・UNC・予約名は内側に収まっても形式拒否される (Task 1)。
3. 自動検出のSDパスを含め秘密が応答に出ない (Task 1・2)。
4. 展開失敗・未生成は成功扱いされない → エラーになる (Task 3)。
5. 削除済みIDの残存も再解除できる (Task 2・4)。
